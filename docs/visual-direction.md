# 主动提取与实现视觉细节

制作方负责从完整口播中判断、提取并实现画面细节。用户提供原片、校准原话并在审核时提修改意见即可，不需要每期再列“还可以画什么”。具体要求来自2026-11-18用户反馈，适用于后续所有期数。

## 每期必达的质量标准

**细节决定质感与成败。画面细节的真实性、完整性和精细程度属于正常制作要求，不能粗制滥造。** 制作方要在用户审核前主动设计、实现并检查，不能把“能播放”“接入了组件”或“多了动画”当作完成标准。

真实性落实到物件结构、界面操作、空间关系和动作结果的可信一致；风格化插画和简化物件也要讲得通。它不要求每张图都照片级写实，更不能靠编造经历、聊天、统计或事实来制造真实感。

- **形体与操作可信**：对象有足够的辨认特征，比例与连接关系合理；按钮、输入、保存和结果按照可理解的顺序发生。
- **空间与材质一致**：厚度、接触、前后遮挡、透视、受光与阴影互相支持；避免物件悬空、穿透、无缘由变形或风格割裂。
- **动作有可见结果**：运动方向、速度、尺度变化和前后状态连续，对应口播语义；避免靠循环漂浮、粒子或换字假装内容推进。
- **细节能被看见**：在手机观看尺寸检查主体、字幕及必要界面信息，主次清楚；不能把不可辨的小字和装饰密度当作精细。
- **画面提供观看价值**：帮助观众认出对象、理解变化或进入环境/情绪。每个关键场景都要经得起去掉标题后的辨认检查。

## 从内容判断画面

先逐段确定观众需要认出、理解或感受到什么，再选择呈现形式。每个重要语义段在director-plan写下：

1. **对象与环境**：可见的人、物件、界面、场所、作品是什么？哪些空间关系帮助理解？例如电脑网页、群资料页、书本、地球和远空。
2. **辨认细节**：少了哪些特征就不像这个东西？设备的外壳/边框、浏览器地址栏、群头像与导航、书脊与纸页、火箭的鼻锥/舷窗/尾喷口等按对象选择，不机械照抄。
3. **动作与结果**：什么行为表现口播里的变化？输入后保存、编辑后网页改变、点火后地球远去。动作有因果和可见结果，不能只换一行解释文字。
4. **构图与尺度**：对象适合局部特写、环境全景还是全屏沉浸？不要将每种场景都塞入同一白卡。人物可在环境镜头淡出，声音和字幕持续，回到个人态度时再出现。
5. **材质与空间**：挑能提高可信度的光影、厚度、遮挡、透视、接触阴影、远近层次和运动差异。细节服务焦点，避免把界面字越堆越小。
6. **时钟与承接**：用真实词锚触发；先给辨认时间，再发生动作，再留结果。纯口播/静态场景最长4秒；较长镜头必须持续推进内容，不能靠粒子漂浮或换标题重置时间。

这些问题由制作方完成判断和落实，不变成逐项向用户提问的表单。只对缺失原话、无法核实的事实或影响授权范围的问题提问。导演方案不是终点，要把选定细节做进实际画面，再按正常流程预览和审查。

## 选择实现方法

- 需要辨认真实人物、作品、事件、地点或证据时，复用准确素材或主动查找可靠来源，记录对应关系及权利状态。
- 界面操作、普通物件和可控制的场景动作，优先直接用HTML/CSS/SVG绘制；做出可辨认结构和操作细节，不把文字卡当成物件。
- 自绘难以达到需要的辨认度时，主动选用合适的开源icon、插画或其他可用素材；核对许可、署名与改编要求，保留来源并下载到本地。不要因为手绘某个复杂对象困难，就退回全段文字动画；可以用叙事等价、观众易辨认的简化物件。
- 允许用小火箭表示“离开地球”这种动作意象，不冒充小说中的官方舰型或真实航天记录。示意无需伪装成照片；真实感来自可信结构、空间和动作的一致性。
- 只在准确素材确实不可得或该段以真实人物态度为重点时保留人物，不能把“没有现成组件”当作停止视觉设计的理由。必要能力做成公共组件，不写期号分支。

## 审查画面是否有价值

静音看画面，是否能认出正在谈的对象和发生的变化？去掉标题后，画面是否仍提供环境、关系、动作或情绪？细节是否在手机尺度可见、主次清楚？动作的起始和结果是否能对应原话？相邻镜头是否补充了新信息或视角？

如果只能靠一段标题解释自己画了什么，就返回对象、环境与动作重新设计。数量、装饰密度或新组件名称不代表视觉质量；不要为了热闹添加无关细节。用户审核负责调整成品，不负责每期代替制作方发掘画面可能性。


## 交付前落实

制作方按关键场景完成细节与真实感审查，先看实际画面，再检查完整动作及前后衔接；静帧与连续观看分别记录。导演方案中留下简短的“实际查看区间/尺寸 → 发现的问题 → 修复与复查结果”，已有正常审查记录可直接补充，不另外建立打分系统或用户审批环节。

发现粗糙、违和、关键结构缺失、动作不成立或文字代替必要场景时，由制作方先补做和修复，再继续正常交付。用户审核用于反馈和细节调整，不承担替制作方完成基础设计与自查的责任。不能仅因技术检查通过就将direction标记ready；完成范围与未完成项始终如实记录。
