# English Journal 制作手册

本手册定义每期默认执行的完整制作流程。降噪、原声静音检测和口播响度处理是必要前处理；技术检查、选帧/预览、连续审查、封面与视频本地导出也属于正常制作，无需逐项请求恢复。执行记录必须对应实际完成情况，历史未执行不等于当前暂停。

本手册、AGENTS、cover-workflow和本仓库配置完整定义制作标准，常规制作无需读取其他业务项目或历史聊天。新机器准备见environment.md；来源沿革单独保留在provenance.md。当前配置和明确的用户指令优先于历史来源。

## 1. 建立期数与原片身份

每期使用 `public/epXX/<edition>/` 和 `output/_work/epXX/<edition>/`。原片另存且不覆盖，所有制作清单记录SHA256。相同期号的不同录音属于不同原片，不能互套字幕和切点。

先决定逻辑画布1080×1920/30fps。原录音若不是CFR30fps，另建同钟的CFR工作副本并保留真正原片，记录转码关系；不能只改视频帧率元数据，也不能借转码偷偷加速。静音剪辑脚本要求CFR30工作原声。

## 2. 降噪识别副本与真实转写

```sh
npm run denoise -- --video /path/to/working-original.mp4 --episode 11 --edition journal
npm run transcribe -- /path/to/printed-denoised-video.mp4 output/_work/ep11/journal/asr.json
```

DeepFilterNet默认6dB衰减上限，户外才选12dB。脚本使用本工程.cache/asr-tools下的本机工具，或DEEP_FILTER_BIN/PATH显式提供的工具，不搜索相邻项目；相同输入哈希、档位、工具版本复用缓存。独立副本位于work/denoise，原片不原地替换。处理保留视频流，补回模型延迟造成的短尾音并检查同钟；失败停止，不能把未处理原声冒充成功结果。

Whisper脚本使用本工程.cache/asr-models/whisper-large-v3-turbo，也可通过LOCAL_ASR_MODEL/--model指定已有目录，不搜索相邻项目。使用安装了mlx_whisper的Python环境，不自动下载模型。已有模型可直接复制到上述目录，无需重新下载。词级时间必须来自实际音频；转写不是用户原话的最终裁决。

已有用户校准字幕时，保留它，不因改去噪重新覆盖原话。人工核对识别分歧、断句与译文；保留口语语法、口音和表达，不把语法纠正写回原话。

## 3. 依据未降噪原声预剪

```sh
npm run trim -- --video /path/to/working-original.mp4 --words output/_work/ep11/journal/asr.json --out output/_work/ep11/journal/trim
```

默认只产出 `trim-report.md`、`edit.json`、`words-program.json`。保守静音阈值−60dB，至少1秒的候选空隙，两端各留0.5秒，且不得与任何识别词相交；ASR漏词不是删除依据。没有安全区间就保留。语义重说、误起、表达性停顿由制作方结合原声另行判断，脚本不会按识别文本自动删词。

agent审查报告和原声，确认候选满足上述保守规则后，直接在原命令加 `--apply`；不把安全静音剪辑设成重复的用户审批。只有会改变原意或无法判断的语义删改才询问具体问题。脚本校验原片和词表身份与报告一致，再生成独立program.mp4；原片不替换，失败不覆盖已完成版本。视频和原声按同一EDL裁剪，输出帧数与清单相符。

以上保守静音政策是本项目默认标准；旧示例已获批准的剪辑不自动重新执行，也不强制恢复已确认的停顿。新片如明确要求更紧的节奏，再另拟方案。

## 4. 同步字幕与动作时间轴

原片时钟只用于源入出点；成片时钟用于词表、字幕、标题、图形动作、音效。不能将原片秒数填进成片帧字段。

trim生成的words-program.json已为成片30fps帧。根据它组织双语字幕，不跨过真实停顿延长字幕，英文与已确认词序一致。输入bilingual.json：

```json
{
  "captions": [{"from":0,"to":45,"english":"Learning to listen.","chinese":"学习倾听"}],
  "words": [
    {"from":0,"to":15,"text":"Learning"},
    {"from":15,"to":23,"text":"to"},
    {"from":23,"to":45,"text":"listen."}
  ]
}
```

edit.json中的cuts格式为 `{sourceIn,sourceOut,from,reason}`，全部原片/成片30fps帧，区间半开，输出连续，源片顺序递增，默认不变速。一个词跨切点说明方案不成立，应回到原声修剪辑，而非截断字幕掩盖问题。

## 5. 剪后降噪与口播响度

对剪好的**原声**program再生成降噪副本；未发生裁剪则可复用第一阶段结果。不能将已降噪的识别副本再次当原片去噪，不能用降噪后的能量检测删静音。

```sh
npm run denoise -- --video output/_work/ep11/journal/trim/program.mp4 --episode 11 --edition journal
npm run voice -- --input /path/to/printed-denoised-program.mp4 --output output/_work/ep11/journal/voice.wav
```

voice步骤只处理口播：先提取同钟48kHz单声道PCM，测整段综合响度与真峰值，计算到−18 LUFS的固定增益，并预留约−2 dBTP。若达到目标需破坏动态，优先峰值安全，允许偏低并记录peakLimited，不按字句拉平，不强制压缩。通常接受−19～−17 LUFS，不能把手机音量50%当文件响度标准。

输出WAV与同名JSON记录原始身份、固定增益、处理前后测量和时长。输出存在时拒绝覆盖。处理后播放增益保持1，防止文件增益与media.volume重复放大；确需手动调整时先依据测量决定。原声、处理副本和记录都保留。

## 6. 导入与语义导演

```sh
npm run episode:new -- --episode 11 --edition journal \
  --video output/_work/ep11/journal/trim/program.mp4 \
  --source /path/to/working-original.mp4 \
  --edit output/_work/ep11/journal/trim/edit.json \
  --audio output/_work/ep11/journal/voice.wav \
  --transcript /path/to/bilingual.json --title "Learning to Listen" --select
```

程序校验身份/时钟后复制到public，不覆盖已有edition。导入只生成draft清单与director-plan骨架，不把默认全片口播当成高质量剪辑已完成。

画面细节的真实性与完成度是每期必达的制作要求：结构、操作、空间、材质和动作结果应可信，细节在手机尺寸可辨，不能粗制滥造或用简单文字动效替代必要场景。由制作方主动设计、实现和自查，用户在审核时提出调整即可。

制作方先按[主动提取与实现视觉细节](visual-direction.md)逐段判断对象、环境、辨认细节、动作结果、尺度、材质与运动关系，选定并落实自绘、准确图片或有合适许可的开源素材。用户不承担每期列画面清单的工作，审核只用于修改成品细节。画面设计不能在填完方案或选择已有组件后就停止。

修改画面前填写导演方案：一句话主旨、语义段、原话依据、观看对象、起始→动作→结果、人物位置为何保持/变化、触发词、相邻承接、来源、未完成项。几句话可组成一镜。标题负责点题，图解负责表现关系；不能全片只是换标题，也不能为了动画打断表达。

公共组件为speaker/media/contrast/sequence/flow/comparison/evidence/dialogue/timeline/scene/transformation/relationship/map/spaceflight/emotion/browser/group-chat/closing；每期数据独立，新增主题不修改公共renderer的期号判断。必要的新视觉关系再扩展公共组件，不拷贝一整期源码。

有真实细节需要观众辨认时用evidence：完整原图→词锚框选→细节放大；有两方真实往返或明确标记的内心想法时用dialogue，保留最近三条；经历包含时间先后与转折时用timeline，保留轨迹并展开当前事件。三者使用chip人物，不新配音、不替换字幕，具体字段、限制与每类两段示例见[语义画面组件](visual-components.md)。不自动重做已确认的历史作品；本期实际画面按第8节完成预览和连续审查。

故事中需要看清谁在哪里、做了什么时用scene；同一组对象从散乱到有序时用transformation；相互影响、阻碍或循环用relationship；地点间的行程用map（明确示意、非比例，不冒充地理导航）；个人情绪发展用emotion（保持hero人物，titles=[]，不打分）。前四者使用chip；字段与每类两段示例见[叙事组件](narrative-components.md)。它们只表达已确认口播里的关系，不把示例自动当作用户经历。

连续纯口播、静态画面或只有装饰动效的同场景最长4秒；换标题或shot ID不能重置时长。超过4秒的镜头需要内容持续推进，例如浏览器操作、手机群名编辑或飞船航行；循环浮动、背景纹理移动不算叙事推进。quality对连续纯口播给出时长提示，其余组件仍须实际审查，不能用组件名称自动宣称满足。

讲具体对象时先让观众看见物件：browser是带屏幕、浏览器与开发面板的电脑；group-chat是带状态栏、群资料、编辑键盘和保存过程的手机；media的book样式是保留真实封面的实体书。它们的可复用字段见[语义画面组件](visual-components.md)。界面通过代码绘制，明确标为示意；概括性话题不能冒充真实聊天记录。

环境与尺度需要时主动使用全屏场景。例如spaceflight通过星空/银河、地球、火箭进入与点火、地球远去表现离开，不局限于白卡箭头图；此段人物淡出但同一视频/音轨节点和字幕时钟保持，结束后返回人物。深色环境中的标题与品牌用浅色，字幕共用既定样式。

### 具体事件、地点、场景和人物的配图

全文阅读后列出具体事件、地点、场景、人物、组织/战队与作品，逐项写明：原话/词锚、要让观众认出什么、是否配图及理由、素材来源、出现与退出区间。主动考虑真实配图，不要求用户逐张提出，也不为每个名词凑一张图片。

例如一段赛事口播，可以按实际内容安排“战队/选手→对应比赛现场或关键赛况→真实庆祝画面”；讲地点可先展示当地环境，讲人物可展示本人。图片负责对象与背景，动态图解负责机制与关系，个人感受与结论让口播人物承担。只选有作用的画面，同一对象跨句保持，不按字幕切换频率换图。

需要素材时先复用现有准确素材，再联网查找官方赛事、主办方、当事人/组织或可靠报道。真实事件先核对赛事、年份、阶段、结果和人物；不能用另一届、另一场比赛或另一队的照片暗示本次事件。若原话存在事实分歧，记录并提示用户，不擅改已确认字幕，也不通过图片把分歧当成已核实事实。

将来源记录在本期work/assets-sources.md：来源页面、原图链接、作者/机构、日期、使用许可或权利状态、对应原话、选用理由和使用区间。下载的正式素材存本期public目录，由media/comparison/evidence或timeline组件引用；渲染时只读本地素材。来源页面不等于已获使用许可；无准确可用素材时保留人物或明确示意，不以AI生成图冒充真实现场。

通过统一细框、裁切、字阶和动作融入青绿赤陶系列，保留照片中的真实队服、标志和关键信息，不强行染绿。图片可以成为主画面，口播声音连续，人物收放按语义决定；字幕仍在最高层。

## 7. 品牌、边距和声音层级

project.config.json集中通用参数，brand.config.json集中身份与风格。账号张木示、圆标Z；完整slogan紧跟账号名下方。视频除账号中文名和中文字幕外，画面文字使用英文；独立封面的本期主题使用中文，系列标识和slogan保留英文。

系列色板为青绿赤陶：浅灰绿底#f4f6f3、深青绿主文字与常规标题#173d3a、赤陶强调#a85134、次文字#61716b、细框#cfd9d2、白色卡片#ffffff。视频、封面和片尾共用，赤陶用于Z和重点信息；点赞红、收藏金保留互动含义。

核心文字左右各100px，按用户要求对称留白，1080画布上的可用宽度880px；字幕固定y1500，英文52/中文34、层级最高；固定白字、细深色描边和轻短阴影，适配明暗背景，不随画面逐帧切换黑白。样式由project.config.json集中配置，默认无底条、无光晕。人物、照片和图解可以延展全画布、经过字幕背后，不能因安全区将主体缩在上半部。安全距约束关键信息而非所有画面；位置以本项目配置及当前用户指令为准。

口播段转场/切换/标题使用柔和气流与纸声，音量0.16–0.22起步，不密集堆叠。片尾Like/Save/Follow依次动作，红心、金黄五角星、Z头像加号变勾；共用短音效按24/40/66帧触发。三秒片尾独立于原口播时钟，整片和JournalOutro共用局部Sequence。

片尾以“账号身份＋关注”为主：大Z、张木示、紧接账号下的完整slogan、主要Follow按钮，Like/Save作为下方较小的辅助动作。整体居中，移除重复系列名和Keep showing up.，不使用三个等权大卡片。所有动作继续共享原有状态和音效时钟。新布局按常规制作完成动态与听感审查，完成范围如实记录。

## 8. 预览、审查与制作状态

npm run dev打开同一个正式合成；修改公共JSON后刷新合成重新载入。agent按制作需要直接使用check/test/build/previews/sample，完成字幕、构图、动效和声音的审查；用户可以补充校准或反馈，常规检查不依赖用户另行批准。

transcript=confirmed表示原话和译文已核对；direction=ready表示导演方案已落实并完成实际代表段审查；cover.status=approved表示人物、主题与封面布局已实际审查。它们是质量记录，不是要求用户逐项点击许可的流程。用户校准结果优先保留，agent完成其余核对后如实更新；未实际完成不能仅靠改状态放行。

先看完整代表语义段及前后交接，再扩展全片；技术检查看素材/时钟/帧数/字体/字幕边界/声音，导演检查看对象/关系/重复/视线/停留，不能互相替代。需要额外审片时按问题范围使用，不作为强制打断或额外审批。不能把静帧当连续观看、把机器测量当实际听感。

交付前完成细节与真实感审查，具体标准见[视觉导演标准](visual-direction.md)：检查关键物件/界面的辨认特征与操作逻辑、比例/透视/遮挡、材质/光影、运动连续性和手机观看可读性。按关键场景在导演方案中记录实际查看区间/尺寸、发现的问题、修复与复查结果；不能仅以组件数量或技术检查通过证明精细程度。发现粗糙或违和先修复再交付，由制作方完成，不另设用户逐项审批。

用户只要求修改、先预览或明确不要导出时，按该次范围交付工程；正常“制作一期”则补齐审查后继续本地导出，不再询问是否允许常规步骤。

## 9. 导出与交付

本地导出属于制作任务，必要检查和审查完成后直接执行；对外发送才按用户明确指令单独进行。默认 `npm run render` 为scale2/2160×3840；1080p为scale1，2K为4/3。逻辑画布1080×1920不变，不在代码里到处乘scale。PNG中间帧、CRF16、单浏览器并发，画面和字幕细节优先；提高分辨率不能恢复原片没有的细节。

导出前静态契约和实际输入保护仍为程序的一部分：原片身份、帧数、音轨时长、已确认状态、素材缺失均能停止。导出母版位于work，最终混音只编码不再全局响度归一，以保留网页确认的口播/SFX比例。最终AAC真峰值≤−1dBTP，帧数/尺寸/音轨核对后才原子替换成品；旧版先备份。

口播目标−18 LUFS只针对口播。不要用包含静音片尾和音效的整片响度假冒口播测量，也不要将全部音轨一起强拉到−15。与预览不一致时先修前置声音处理，不能靠最后一步补救。

成品目录交付video.mp4、cover.png与post.md。post由本期publication字段生成，中文标题20字符以内，正文为一小段自然文案；先结合完整口播写好再导出，不能拼接字幕冒充发布文案。正式视频导出会同步生成post.md，命令和飞书交付见publishing.md。

封面沿Journal青绿赤陶品牌，使用纸感、大字阶和人物剪贴，中文主题提炼本期主线与最强真实情绪/冲突，写得生动、有态度，不只给中性总结；用户给出的主题优先采用，不编造经历或夸大立场，不引入纠错内容。JournalCover使用独立3:4（1080×1440）构图；当期人物选自然表情并去背景，透明PNG接入母版，不将带视频背景的矩形截图当完稿。选帧、抠图、确认与导出步骤见cover-workflow.md。

最终提供视频/封面路径、实际尺寸/时长、验证范围和遗留问题。没有导出就只说工程更新，不拿旧样片当新成片。

## 10. 独立制作的完成标准

准备环境不需要克隆其他业务项目，按environment.md准备运行依赖、模型及本期媒体即可。本仓库已经写明全部需要执行的参数、制作顺序、素材保护和品牌要求，不以“参考某项目”代替具体标准。

逐期保留原片身份与剪辑映射、真实词表及确认字幕、语义导演方案、配图来源、音频处理记录、封面参考/抠图与用户确认状态。可以自动校验的契约保留在validate/quality/delivery，叙事与听感按第8节实际查看；不以配置正确冒充作品质量达标。缺工具、素材或确认时说明具体缺项，不能读取另一项目的旧结果来补造通过证据。历史来源和许可见provenance.md及licenses，只作沿革记录。
